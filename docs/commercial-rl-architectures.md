**이 문서는 등급표가 아니라 명세서입니다.** 실제로 상용 운영에 들어간 RL 시스템을
**관측 → 정책 구조 → 행동 → 학습 → 보상 → 안전 계층 → 결과 수치** 순서로 같은 형식에 맞춰 적었습니다.

## 1. ANYmal 보행 — 로봇 RL 상용의 원형 `[논문]`

**가장 잘 문서화된 상용 로봇 RL입니다.** ETH Zurich 계보이고 ANYbotics가 상용화했습니다.

### 1.1 실행 구조

| 층 | 내용 |
| --- | --- |
| **관측** | 관절 각·속도, **이전 행동**, 몸통 각속도, **중력 벡터**, 명령 속도 (+ 지각형은 높이 샘플) |
| **정책 구조** | MLP. 지각형은 **GRU 기반 recurrent belief state encoder** |
| **행동** | **목표 관절 위치.** 정책 출력을 스케일해 **공칭 자세(nominal joint configuration)에 더함** |
| **정책 주기** | **50 Hz**, 온보드 컴퓨터 |
| **하위 루프** | **PD 컨트롤러가 토크 계산.** 메인 제어 루프·상태추정은 **400 Hz** |

**행동 정의를 그대로 보십시오** — `목표각 = 공칭 자세 + 스케일 × 정책출력`.
**정책은 공칭 자세로부터의 편차만 냅니다.** 이게 우리 서베이의 L2a이고, 상용 시스템의 실제 형태입니다.

### 1.2 지각형의 핵심 — gated belief encoder `[논문]`

Miki 등(Science Robotics)의 구조입니다.

1. **교사**: 시뮬레이터 특권 정보(정확한 지형)를 받고 RL로 학습
2. **학생**: 노이즈 있는 관측만 받고 교사 행동을 모방 + **환경 실제 상태를 복원**하도록 학습
3. **gated encoder**: **외수용 감각(지형 인식)을 얼마나 통과시킬지 결정하는 적응적 게이팅 계수**를 학습
4. **디코더**: 같은 게이트로 **특권 정보와 높이 샘플을 복원** → 복원 손실이 belief state가 실제 환경 정보를 담도록 강제

**게이팅이 왜 중요한가** — 지형 인식이 틀렸을 때(눈·풀·반사) **자동으로 자기수용감각에 더 의존하게 됩니다.**
지각 실패를 정책 안에서 처리하는 구조입니다.

### 1.3 학습 규모 `[논문]`

Rudin 등(CoRL)의 대규모 병렬 설정입니다.

| 항목 | 값 |
| --- | --- |
| 병렬 에이전트 | **4,096** |
| 하드웨어 | **단일 워크스테이션 GPU** |
| 평지 정책 | **4분 미만** |
| 험지 정책 | **20분** |
| 커리큘럼 | **게임식 난이도 진행** — 수천 대 병렬 학습에 맞춰 설계 |
| 코드 | 오픈소스 |

### 1.4 결과물 `[논문]` + `[문헌]`

| 결과 | 수치 |
| --- | --- |
| 알프스 하이킹 | **1시간 코스를 인간 권장 시간 안에 완주** |
| Etzel 등반 | **2.2 km, 고도 상승 120 m, 경사 최대 38%** — **공식 표지판의 인간 소요 시간보다 빠르게 정상 도달** |
| 상용 배치 | ANYmal X는 **폭발 위험 환경 인증**, PETRONAS 해양 플랫폼 |

## 2. AlphaChip — 배치를 게임으로 `[논문]` + `[벤더]`

### 2.1 실행 구조

| 층 | 내용 |
| --- | --- |
| **문제 정의** | 칩 캔버스를 **격자로 분할**. **스텝마다 매크로 하나를 유효 격자 좌표에 배치**, 전부 배치할 때까지 |
| **관측** | 넷리스트 인접 관계, 노드 특징, **현재 배치할 매크로** |
| **인코더** | **edge 기반 그래프 신경망** — 상호 연결된 부품 간 관계를 학습하고 **칩 간 일반화** |
| **상태 임베딩** | edge · 매크로 · 넷리스트 메타데이터 임베딩을 **concat** → FFN → 학습된 표현 |
| **정책 헤드** | 배치 가능 위치에 대한 **확률 분포** |
| **가치 헤드** | 현재 배치의 **기대 보상** |

### 2.2 보상 — 싸고 근사적으로

**보상 = 근사 wirelength(HPWL) + 근사 congestion(배치된 넷리스트가 소비하는 라우팅 자원 비율)의 가중 평균.**
목적에는 density도 포함됩니다.

**정확한 지표를 쓰지 않습니다.** 실제 배선·혼잡도를 매 스텝 계산하면 학습이 불가능하므로
**빠르지만 근사적인 대리 보상**을 씁니다 — 패턴 2.

### 2.3 결과물

| 결과 | 수치 |
| --- | --- |
| 생산 사용 | **TPU v5e · v5p · Trillium** — 세대가 갈수록 배치 블록 수와 배선 감소폭 증가 |
| 배포 | 여러 TPU 세대에 **tape-out** → 전세계 구글 데이터센터 가동 |
| 확산 | Alphabet 내 다른 칩, **MediaTek** 등 외부 채택 |
| 속도 | 레이아웃 **수 시간** 내 생성 |

> **⚠ 재현성 논쟁이 공개돼 있습니다.** 인용 시 같이 말하십시오.

## 3. DeepSeek-R1 — 4단계 파이프라인 `[논문]`

**오늘 가장 큰 상용 RL(LLM 후속학습)의 공개된 레시피입니다.**

### 3.1 4단계 구성

| 단계 | 내용 |
| --- | --- |
| **① Cold start** | **수천 개**의 긴 사고사슬(CoT) 예시로 V3-Base를 SFT. **의도적으로 작게 유지** — RL이 나중에 발견할 추론 스타일을 과도하게 제약하지 않기 위해 |
| **② 추론 지향 RL** | R1-Zero와 같은 RL. **언어 일관성 보상**을 추가(CoT 내 목표 언어 단어 비율)해 언어 혼용 해결 |
| **③ Rejection sampling + SFT** | 글쓰기·롤플레이 등 범용 성능 보강 |
| **④ 전 시나리오 RL** | 2차 GRPO. **규칙 기반 보상 + 모델 기반 선호 보상**(유용성·안전성)을 함께 |

**①의 설계 의도를 눈여겨보십시오** — 사전 지식을 **넣되 적게** 넣습니다.
많이 넣으면 RL이 탐색할 공간을 미리 닫아버리기 때문입니다.

### 3.2 알고리즘과 보상

| 항목 | 내용 |
| --- | --- |
| **GRPO** | PPO의 계산 효율 변형. **별도 가치 모델 불필요** — **그룹 정규화 보상**으로 이득 추정 |
| **보상** | **규칙 기반만** — 정확도, 형식, 언어 일관성 |
| **설계 의도** | **신경 보상 모델을 의도적으로 회피** — 대규모 RL에서 **보상 해킹을 막기 위해** |

**이 한 줄이 우리 보상 거버넌스에 직접 걸립니다.** 업계 최대 규모 RL의 결론이
**"학습되는 보상 모델을 쓰지 말고 규칙으로 검증하라"**입니다.

## 4. Google 데이터센터 냉각 — 검증 계층의 교과서 `[벤더]`

### 4.1 실행 구조

| 층 | 내용 |
| --- | --- |
| **주기** | **5분마다** 수천 센서 스냅샷을 클라우드로 |
| **예측** | **심층망 2개 앙상블**이 **1시간 후 온도·압력을 예측** → 권고 행동을 시뮬레이션해 운영 제약 위반 여부 확인 |
| **행동 선택** | 안전 제약을 만족하면서 에너지 소비를 최소화하는 행동 선택 |
| **사전 필터** | 에이전트가 **모든 행동의 신뢰도를 계산해 낮은 것을 후보에서 제거** — 2계층 검증 이전 단계 |

### 4.2 안전 계층 — 이 문서에서 가장 중요한 부분 `[벤더]`

```
  AI 행동 결정
      ↓
  [검증 1]  클라우드 — 운전자가 정의한 안전 제약 목록에 대조
      ↓
  [검증 2]  로컬 제어 시스템 — 자체 제약으로 재검증
      ↓
  실행
```

- **운전자는 언제든 AI 제어 모드를 종료**할 수 있고, 그 순간 **기존 규칙·휴리스틱 자동화로 무결절 전환**됩니다
- 즉 **AI는 항상 폴백 가능한 상태로만 돌아갑니다**

### 4.3 결과물

| 결과 | 수치 |
| --- | --- |
| 냉각 에너지 | **40% 감소** (초기), 광범위 배치 후 **평균 약 30%** 안정 |
| PUE | 전기 손실·비냉각 비효율 제거 후 **오버헤드 15% 감소** |
| 절감액 | 2024년 기준 연 **2~3 TWh** ≈ **2~3억 달러** |

> **⚠ "이게 RL인가" 유보.** 위 구조는 **예측 모델 + 제약 하 행동 탐색**입니다.
> 모델 기반 계획에 가깝고, 정책을 보상 경사로 직접 최적화하는 형태로 서술되지 않습니다.

## 5. CDU 압력 제어 — 오프라인 RL로 안전을 확보 `[논문]`

**정유 공정의 업계 최초 전규모 상용 배치. 이 문서에서 안전 설계가 가장 참고할 만합니다.**

### 5.1 실행 구조

| 층 | 내용 |
| --- | --- |
| **문제** | 19만 배럴 원유 증류탑(CDU)의 **압력 제어** |
| **데이터** | **여러 운전자의 수동 조작 로그** |
| **학습 방식** | **오프라인 RL** — 가동 중인 시스템과 상호작용하지 않음 |
| **알고리즘** | **SAC**를 오프라인 데이터로 학습. **conservative loss + Return-to-Go**를 통합해 추정 문제(과대추정) 해결 |
| **문제 정의** | MDP 설계 + **실시간 DB(RTDB)**로 연속 데이터 통합 |

### 5.2 왜 이 구성이 상용화를 통과했나 `[논문]`

**논문이 안전성 근거를 이렇게 적습니다** —
**"가동 중인 시스템에 간섭하지 않고, 추가 운영 비용도 발생시키지 않는다."**

**탐색을 아예 안 합니다.** 운전자들이 이미 만들어 놓은 로그에서 정책을 뽑아냅니다.
실물 공정에서 RL 탐색이 안전 문제라는 것을 **알고리즘 선택으로 우회**한 것입니다.

### 5.3 결과물

| 결과 | 수치 |
| --- | --- |
| 운전자 개입 시간 | **84% 감소** |
| 누적 오차 | **12.8% 감소** |
| 압력 제어 변동성 | 유의하게 감소 |

## 7. Amazon Robin — 상용 최대 조작 시스템이 딥 RL이 아닙니다 `[논문]`

**패턴 6. 이 문서에서 가장 반직관적인 항목입니다.**

### 7.1 실행 구조

| 층 | 내용 |
| --- | --- |
| **문제** | 픽 대안들을 **실시간으로 랭킹**해 가장 유망한 것을 우선 실행 |
| **모델** | **얕은 기계학습 모델** — **어떤 특징이 예측에 중요한지 평가할 수 있도록 의도적으로** |

| **학습 데이터** | **394K+ 실제 생산 픽** |

### 7.2 결과물

| 결과 | 수치 |
| --- | --- |
| 처리량 | 일 최대 **500만 패키지** 단품화 |
| 누적 | 평가 기간 **2억+ 패키지** 조작 |
| 비교 | **수작업 설계·휴리스틱 대안의 한계를 극복하고 성능을 능가** |

> **읽는 법**: 세계 최대 규모 로봇 조작 시스템의 핵심이 **부스팅 트리 앙상블**입니다.
> **딥 RL이 아니라는 사실이 이 시스템의 약점이 아니라 설계 선택입니다** —
> 특징 중요도를 볼 수 있어야 운영이 가능하기 때문입니다.

**Waymo의 RL 위치는 명확합니다** `[논문]` — 지도학습 행동 모델이 test-time 분포 이동을 겪으므로
**폐루프 RL로 미세조정**하고, Waymo Open Sim Agents 챌린지에서 전체 성능과 **충돌률**이 개선됐습니다.
**즉 RL이 처음부터 정책을 만드는 게 아니라 이미 있는 모델을 고칩니다.**
