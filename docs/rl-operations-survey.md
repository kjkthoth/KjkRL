## 0. 세 줄 요약 — 보고용

1. **간부진이 맞습니다.** 맨땅(무작위 초기화 단독)에서 시작하는 것은 업계 표준이 아니라 **사다리의 맨 아래 한 칸**이고, 접촉이 많은 조작 태스크에서는 거의 선택되지 않습니다. 표준은 **자산·템플릿 재사용 → 스크립트/프리미티브 → 시연 → 특권정보 교사-학생 증류 → 파운데이션 모델 후속학습** 중 가장 높이 닿을 수 있는 칸에서 시작하는 것입니다 `[문헌]`
2. **동시에 제 기존 인식도 틀리지 않았습니다.** "무작위로 움직이다 점수 좋은 정책으로 수렴"은 **PPO 내부에서 실제로 벌어지는 일**입니다. 다만 그것은 **알고리즘의 사실**이고 **프로젝트의 착수 지점이 아닙니다.** 두 층을 구분하지 않은 것이 인식 격차의 원인입니다 (2절)
3. **우리 목표(cable/cloth 조작)는 이미 산업 레퍼런스가 있습니다.** Newton의 변형체 솔버로 **삼성이 냉장고 조립 라인 케이블 조작**을, **Skild AI가 GPU 랙 조립 커넥터 삽입**을 하고 있습니다 `[문헌]`. 우리는 미개척지가 아니라 **레퍼런스가 존재하는 영역**에 들어갑니다 (5절)

**그리고 이 서베이가 새로 찾아낸 제약 하나** — 현재 kitless 스택은 사다리의 **L3·L5 두 칸(시연 기반 학습, 카메라 기반 정책)을 구조적으로 못 씁니다** `[문서]`. teleop·mimic·RTX 렌더가 빠져 있기 때문입니다. 이것이 8절 요청 목록의 1번 근거입니다.

## 1. "주먹구구"의 정체 — 결핍 두 가지

간부진이 본 것을 구체화하면 이렇습니다. 우리 리포는 **설치 규율은 이미 좋습니다** — 근거 등급, 커밋 고정, 래퍼, `[미확인]` 추적. 없는 것은 아래 두 개입니다.

| 결핍 | 증상 | 이 문서의 대응 |
| --- | --- | --- |
| **부트스트랩 계층 부재** | 태스크를 새로 쓸 때 무엇을 재사용하고 무엇을 새로 만들지 기준이 없음 → 매번 맨땅 | 3절 사다리 |
| **운영 규율 부재** | 실험을 몇 번 돌리고 무엇을 근거로 "됐다"고 판정하는지 규칙이 없음 → 단일 실행 눈대중 | 6절 규율 |

두 번째가 특히 중요합니다. `[실측]` README 4.3의 cartpole 성공 판정은 **reward -4.07 → 8.28, 10 iteration, 시드 1개**입니다. 첫 통과 증거로는 충분하지만 **성능 주장의 근거로는 쓸 수 없습니다.** RL 문헌은 이 정도 표본에서 나오는 오류율을 정량화해 뒀습니다 — 6.2절.

## 2. 인식 정정 — "무지성 탐색"은 어느 층에 있는가

제가 알고 있던 것과 간부진 말씀은 **서로 다른 층을 말하고 있어서 둘 다 참**입니다.

| 층 | 무작위에서 시작하는가 | 근거 |
| --- | --- | --- |
| **알고리즘 내부** (정책 가중치 초기화, 탐색) | **예.** PPO는 무작위 초기화 정책에서 시작해 이득 추정으로 수렴합니다 | 제 기존 인식 — 맞습니다 |
| **프로젝트 착수 지점** (무엇을 주고 시작하는가) | **아니오.** 자산·보상·태스크 템플릿·교사 정책·시연·사전학습 가중치를 넣고 시작합니다 | 간부진 말씀 — 맞습니다 `[문헌]` |

**즉 "맨땅"의 정의가 문제였습니다.** 정책 가중치는 맨땅에서 시작해도 되지만, **환경·보상·관측·초기 상태 분포·평가 기준은 맨땅에서 만들지 않습니다.** 그건 재사용 대상입니다.

이게 왜 결정적인가 — 접촉이 많은 조작 태스크에서 **탐색이 실패하는 지점**은 알고리즘이 아니라 **태스크 정의**입니다.
케이블을 클립에 끼우는 태스크에서 무작위 정책이 우연히 클립에 끼울 확률은 사실상 0이고, 그러면 보상 신호가 아예 발생하지 않아 **PPO가 수렴할 대상 자체가 없습니다.** 로코모션(걷기)은 무작위 몸부림에서도 전진 보상이 조금씩 나오기 때문에 맨땅이 성립하지만, 조작은 그렇지 않습니다.

**그래서 사다리가 존재합니다.** 사다리의 목적은 "학습을 편하게" 하는 게 아니라 **보상 신호가 발생하는 상태에 정책을 데려다 놓는 것**입니다.

## 3. Part A — 부트스트랩 사다리 (착수 지점 6단계)

아래로 갈수록 사전 지식을 많이 넣습니다. **위에서 아래로 읽고, 우리가 닿을 수 있는 가장 아래 칸에서 시작하십시오.**

| 칸 | 이름 | 무엇을 넣는가 | 언제 쓰는가 | 우리 스택 가용성 |
| --- | --- | --- | --- | --- |
| **L0** | 맨땅 (tabula rasa) | 없음. 무작위 초기화 + 보상 | 저차원·조밀 보상. 로코모션 | **가능** — cartpole이 이것 `[실측]` |
| **L1** | 자산·태스크 템플릿 재사용 | 검증된 env cfg, 솔버 설정, 보상 항 | 유사 태스크가 이미 있을 때 | **가능. 이미 있습니다** (아래) |
| **L2** | 프리미티브 + Residual RL | 스크립트 컨트롤러를 기저로, RL은 보정분만 | 접촉 많고 안전이 걸릴 때 | **가능** |
| **L3** | 시연 기반 (IL + 합성 증강) | 사람 시연 몇 개 → 합성 궤적 다량 | 태스크가 다단계일 때 | **불가** `[문서]` — kitless가 teleop·mimic 포기 |
| **L4** | 교사-학생 증류 | 시뮬레이터 특권정보로 교사 학습 후 실측 관측 학생으로 증류 | 실물 이전이 목적일 때 | **부분 가능** — 학생 관측이 비카메라면 가능 |
| **L5** | 파운데이션 모델 후속학습 | 사전학습된 VLA 가중치 | 언어 지시·범용성이 필요할 때 | **불가** — 카메라(RTX 렌더) 필요 |

### L1 — 우리는 이미 템플릿을 갖고 있습니다

`[실측]` README 6.1·6.2에 기록된 것이 정확히 L1 자산입니다.

- `Isaac-Lift-Cloth-Franka-v0` — `CoupledMJWarpVBDSolverCfg`, `NewtonDeformableBodyPropertiesCfg`, `FrankaDeformablePPORunnerCfg`가 **이미 조합되어 동작하는 상태**
- `isaaclab_contrib.deformable` — `VBDSolverCfg`, `DeformableObject`, `NewtonModelCfg`
- 주석에 "matching the Newton example" — 즉 **Newton 예제 → Isaac Lab 태스크 변환의 참조 구현이 리포 안에 있습니다**

**cable 태스크는 맨땅이 아니라 이 cfg의 변형입니다.** README 6.6의 순서가 이미 L1 전략이고, 이 서베이는 그 판단이 업계 표준과 일치한다는 확인입니다.

### L2 — Residual RL: 스크립트를 버리지 않습니다

`[문헌]` Siemens·UC Berkeley의 Residual RL은 **수작업 피드백 컨트롤러 + 학습된 보정 정책의 합**으로 제어를 구성합니다. 재래식 제어가 잘 하는 부분은 재래식에 맡기고 RL은 잔차만 풉니다.

- 동기가 우리와 같습니다 — **제조 현장에서 RL의 탐색 거동은 안전 문제이고 데이터가 비쌉니다** `[문헌]`
- 임피던스 제어 + residual recurrent RL로 **삽입 태스크를 실물 학습 수 분 내** 습득, 상당한 불확실성 하에서 성공률 94% 보고 `[문헌]` — 원문 대조 필요
- 케이블 쪽에는 **촉각 기반 모션 프리미티브**로 라우팅·조립을 구성한 선행 연구가 있습니다 `[문헌]`

**cable 라우팅에 바로 적용되는 형태** — "케이블을 잡고 클립 방향으로 이동"은 스크립트로 씁니다. RL은 "접촉이 생겼을 때 어떻게 비틀어 넣는가"만 배웁니다. 탐색 공간이 태스크 전체에서 접촉 국면으로 줄어듭니다.

### L3 — 시연 기반: 지금은 못 씁니다

`[문서]` Isaac Lab은 시연 증강 도구를 갖고 있습니다.

| 도구 | 하는 일 |
| --- | --- |
| **Isaac Lab Mimic** | MimicGen 기반. 사람 시연을 객체 중심 서브태스크로 분절 → 강체 변환 → 재조합. **시연 1개에서도 사실상 무한한 합성 궤적** 생성, 병렬 env로 생성 처리량 확대 |
| **SkillGen** | Mimic + 모션 플래닝. 충돌 없는 적응형 궤적 생성 |

**그런데 kitless에서 빠집니다.** `[문서]` README 3절 경로 C의 표에 `teleoperation·imitation learning 워크플로`가 "안 되는 것"으로 명시돼 있고, `[실측]` `il -i`가 설치하는 목록에서도 `teleop`/`mimic`은 kitless에서 못 쓰는 토큰으로 분류돼 있습니다.

**이것이 8절 요청 1번의 근거입니다** — 사다리 한 칸이 설치 경로 선택 때문에 잠겨 있습니다. cable이 다단계 태스크(잡기→경로 따라가기→클립 삽입)라서 **L3가 가장 잘 맞는 칸인데 그게 막혀 있습니다.**

### L4 — 교사-학생 증류: 실물 이전의 표준 형태

`[문헌]` 다리형 로봇 쪽에서 2022년 이후 **주류 방식**입니다.

1. **교사** — 시뮬레이터만 아는 정보(노이즈 없는 상태, 지형 높이, 마찰 계수 등 특권정보)를 받고 RL로 학습. 문제가 쉬워집니다
2. **학생** — 실물에서 실제로 얻을 수 있는 관측(노이즈 있는 자기수용감각, 깊이 영상)만 받고 **교사 행동을 지도학습으로 모방**

**cable에 이게 왜 맞는가** — 변형체의 완전 상태는 노드 수백 개의 위치입니다. 실물에서는 못 봅니다. 시뮬레이터에서는 **공짜로 봅니다.** 그래서 교사에게 전체 노드 상태를 주고 풀게 한 뒤, 학생을 관측 가능한 것(그리퍼 자세, 힘/토크, 촉각, 케이블 키포인트 추정)으로 증류합니다.

`[문헌]` **WireCraft 벤치마크에서 특권 상태 기반 RL이 각 태스크군의 대표 설정을 82% 이상 성공률로 풀었습니다** — "태스크가 제대로 정의됐음"의 확인이고, 동시에 **교사 단계는 실현 가능하다**는 뜻입니다. 어려운 쪽은 학생 단계, 즉 상태 추정입니다.

**우리 스택에서 부분 가능한 이유** — 학생 관측을 카메라로 잡으면 RTX 렌더가 필요해 kitless에서 막힙니다. **자기수용감각 + 힘/토크 + 촉각으로 한정하면 지금 스택에서 됩니다.**

### L5 — 파운데이션 모델 후속학습

`[문헌]` GR00T N1.5는 개방형 VLA(vision-language-action) 파운데이션 모델입니다. 실물 시연 + Isaac Lab Mimic 파이프라인 합성 데이터 + 인터넷 영상 혼합으로 사전학습, 파인튜닝 스크립트 제공, GR-1 조작 태스크 언어 추종 93.3%(N1은 46.6%) `[문헌]`.

**우리 대상이 아닙니다, 지금은.** 카메라 관측이 전제이고 kitless에 RTX 렌더가 없습니다. 언어 지시가 요구사항에 없다면 **L5는 이 프로젝트의 목표로 잡지 마십시오** — 비용만 큽니다.

## 4. Part B — 스택 현황 (2026-08 기준)

### 4.1 Newton은 베타가 아닙니다

`[문헌]` 시간선입니다.

| 시점 | 사건 |
| --- | --- |
| 2025-09-29 | Disney Research·Google DeepMind·NVIDIA가 Newton을 **Linux Foundation에 기여**. Apache-2.0, 벤더 중립 거버넌스 |

| 2026-08 | `[실측]` 우리 체크아웃의 Newton은 **1.2.1** — 1.0 이후 계열로 정합적입니다 |

**보고 시 중요한 함의** — 우리가 고른 물리 엔진은 **한 회사의 실험 프로젝트가 아니라 Linux Foundation 거버넌스 하의 1.x 안정 배포판**입니다. `[실측]` 우리가 쓰는 Isaac Lab 3.0.0-beta2가 beta인 것과 **Newton이 beta인 것은 다른 얘기입니다.** 리스크는 Isaac Lab 쪽에 있습니다.

### 4.2 솔버 구성 — 외부 자료와 우리 실측이 일치합니다

| 항목 | 외부 자료 `[문헌]` | 우리 실측 `[실측]` |
| --- | --- | --- |
| 강체 솔버 | MuJoCo Warp, Kamino | `SolverMuJoCo`, `SolverKamino` |

**권고** — 실물 케이블 샘플 확보 + 최소 계측(굽힘 시험 1종)을 **학습 착수 전** 일정에 넣으십시오. 8절 요청 3번.

### 6.5 보상 설계 거버넌스 — 명세 게이밍을 전제로 하기

`[문헌]` 보상 해킹/명세 게이밍은 예외가 아니라 **기본 발생 양상**입니다. 실무 보상은 대리 지표(proxy)에 의존하고 대리 지표는 굿하트 법칙의 대상이 됩니다. 단일 카메라 평가를 각도로 속인 그리핑 로봇, 경로를 따르는 대신 지그재그 후진을 배운 로봇 같은 사례가 표준 예시로 인용됩니다.

**cable에서 예상되는 형태를 미리 적어 둡니다** `[미확인]` — 실제 발생 여부는 학습해 봐야 압니다.

| 대리 지표 | 예상되는 해킹 |
| --- | --- |
| 케이블 끝점이 목표 근처 | 케이블을 **잡아당겨 늘려** 끝점만 도달 |
| 클립 접촉 판정 | 클립을 **밀어 옮기고** 접촉 판정 획득 |
| 형상 오차 최소화 | 케이블을 **꼬아서** 오차 지표만 낮춤 |
| 삽입 깊이 | 과도한 힘으로 밀어넣어 **손상 유발** |

**규율 두 개.**

1. **보상 항을 추가할 때마다 "이 항을 최대화하면서 태스크를 실패하는 방법"을 한 줄 적으십시오.** 못 적으면 그 항은 검토가 안 된 것입니다
2. **평가 지표는 학습 보상과 분리하십시오.** 보상은 조밀해야 하고 평가는 태스크 성공 그 자체여야 합니다. 같은 함수를 쓰면 해킹을 탐지할 수단이 사라집니다

`[문헌]` 4.5절 15분 레시피가 **"미니멀한 보상 함수"** 를 설계 선택으로 명시한 것도 같은 방향입니다 — 항이 적으면 해킹 표면도 작습니다.

### 6.6 커리큘럼 — 프레임워크가 이미 제공합니다

`[문서]` Isaac Lab에 `CurriculumManager`와 `CurriculumTermCfg`가 있습니다. 커리큘럼 항을 콜러블로 정의해 등록하면 학습 진행에 따라 환경 값을 갱신하고, 반환값은 로깅됩니다. 지형은 `update_terrain_levels()`로 **게임식 난이도 진행**(쉬운 레벨 → 어려운 레벨)을 구현합니다.

**cable에 옮기면** `[미확인]`:

| 커리큘럼 축 | 쉬움 → 어려움 |
| --- | --- |
| 케이블 강성 | 뻣뻣함(강체에 가까움) → 유연함 |
| 초기 상태 | 목표에 가깝게 배치 → 무작위 배치 |
| 공차 | 넉넉한 클립 → 타이트 |
| 단계 수 | 1단계 삽입 → 다단계 라우팅 |

**"강성을 뻣뻣하게 시작"이 특히 값이 있습니다** — 강체에 가까운 케이블은 상태 공간이 작아 보상 신호가 먼저 발생합니다. 2절에서 말한 "보상 신호가 발생하는 상태에 데려다 놓기"의 구체형입니다.

### 6.7 승격 게이트 — 다음 단계로 넘기는 기준을 미리 쓰기

`[실측]` README의 "소형 검증 → 대형 학습" 2머신 흐름은 이미 게이트 구조입니다. **비어 있는 것은 통과 기준입니다.**

**권고 게이트** — 각 단계에서 다음을 만족하지 못하면 다음 단계로 가지 마십시오.

| 게이트 | 통과 기준 |
| --- | --- |
| **G0 스모크** (4060) | 커널 컴파일 에러 없음, 1 iteration 완주, 체크포인트 생성. `[실측]` cartpole은 통과 |

**G2가 핵심 게이트입니다.** 특권 정보를 다 줘도 안 풀리는 태스크는 **관측을 제한하면 당연히 안 풀립니다.** 여기서 실패하면 정책이 아니라 태스크·보상을 고쳐야 하고, **이 구분을 못 하면 그게 주먹구구입니다.**
